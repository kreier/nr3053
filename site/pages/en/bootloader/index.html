Boot Process & U-Boot Bootloaders

Understanding how the MediaTek MT7981B (Filogic 820) boots explains why flashing FIP is much safer than flashing BL2, and why an exposed UART header makes the NR3053 practically unbrickable.

MT7981B 4-Stage Boot Chain

Stage 0 BootROM (BROM)
Immutable Silicon UART Handshake

Hardwired inside the MT7981BA SoC. On power-up, briefly listens on UART0 for a mtk_uartboot handshake; if none arrives, loads BL2 from SPI NAND at 0x000000. Because BootROM cannot be overwritten, UART recovery always works.

Stage 1 BL2 Preloader
Offset 0x000000 · 1 MiB High Risk

ARM Trusted Firmware SPL that initializes the 512 MiB DDR3L RAM and the Dosilicon DS35Q2GBS SPI NAND controller, then loads FIP from 0x400000. Usually left untouched when installing OpenWrt or ImmortalWrt.

Stage 2 FIP (BL31 + U-Boot)
Offset 0x400000 · 2 MiB Web Failsafe + TFTP

Firmware Image Package containing ATF BL31 runtime services and Das U-Boot. Either the stock U-Boot 2022.07-rc3 (supports Web Failsafe & stock-layout OpenWrt 24.10) or ImmortalWrt U-Boot 2025.10 (supports Native UBI, Web Failsafe, DHCP, TFTP, and bootmenu).

Stage 3 Linux FIT / UBI
Offset 0x600000+ Kernel 6.12 / 6.6

U-Boot verifies and boots the kernel + device tree + SquashFS root filesystem from flat firmware (stock / OpenWrt 24.10) or the UBI fit volume (ImmortalWrt 25.12), mounting the writable overlay.

Note on Older NR3053 Units
Some earlier NR3053 hardware/stock batches shipped without the HTTP Web Failsafe server enabled in stock U-Boot. If holding MESH at power-on does not open http://192.168.1.1/, use the SSH Unlock method instead.
