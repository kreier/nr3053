Tools & Troubleshooting

Command reference for nr3053-tools and solutions for the most common flashing, networking, TFTP, and UART recovery issues on the Viettel SDMC NR3053.

quytttb/nr3053-tools Reference

Host-side Python utilities built specifically for the Viettel SDMC NR3053:

Tool Purpose
unlock_nr3053.pyDownloads, patches, and re-uploads the stock router configuration backup to enable SSH & Telnet access (default password becomes admin).
factory/patch_factory_throughwall.pyOffline patcher for an exact 2 MiB NR3053 Factory dump that applies verified through-wall Wi-Fi calibration values, printing before/after SHA-256 checksums without touching the router directly.
 
# Install nr3053-tools
git clone https://github.com/quytttb/nr3053-tools.git
cd nr3053-tools
python3 -m pip install -r requirements.txt

# 1. Unlock SSH/Telnet (after factory reset, password = bottom-label S/N)
python3 unlock_nr3053.py --password YOUR_SERIAL_NUMBER

# 2. Optional: Offline Factory through-wall calibration patch (exact 2 MiB Factory dump)
python3 factory/patch_factory_throughwall.py stock_Factory.bin
python3 factory/patch_factory_throughwall.py --check stock_Factory.throughwall_mtd_Factory_0x0-0x200000.bin

Common Issues & Fixes

Stock Web Failsafe Won't Open

  • Confirm your Ethernet cable is plugged into a LAN port (not WAN) and your PC static IP is 192.168.1.2/24 (for stock U-Boot) or 192.168.1.254/24 (for ImmortalWrt U-Boot).
  • Disable Wi-Fi and any active VPNs on your PC while flashing, and use an incognito browser tab to avoid stale cache.
  • Ensure you held the MESH button (not Reset) before plugging power in and released once the LED turned solid green (~5 s).
  • Some older stock NR3053 batches lack Web Failsafe entirely — use Method 2 (Unlock SSH) instead.

scp Fails with Subsystem or Protocol Error

Stock Dropbear SSH does not implement SFTP. Pass -O to force the legacy SCP protocol (or use WinSCP in SCP mode on Windows):

scp -O immortalwrt-mediatek-filogic-viettel_nr3053-bl31-uboot.fip root@192.168.1.1:/tmp/fip.bin

mtk_uartboot Handshake Timeout or Blank Console After FIP received

  • Verify TX/RX are crossed (Adapter TX ↔ Board RX) and the adapter is strictly 3.3 V (not 5 V).
  • Start mtk_uartboot before plugging in router power.
  • Never open picocom or PuTTY on the same serial port while mtk_uartboot is running.
  • As soon as FIP received appears, hit Ctrl+C in the mtk_uartboot window and open picocom / PuTTY within 1–2 seconds.
  • Confirm you are using the NR3053 RAM payload (bl2-viettel-nr3053-ram.bin), not the Viettel 32X6 payload.
  • If the transfer stalls at high baud, add --bl2-load-baudrate 115200.

TFTP Timeout / File Not Found

  • Check PC IP is 192.168.1.254/24 (ImmortalWrt U-Boot default serverip), with no gateway and VPN disabled.
  • In U-Boot console, verify printenv serverip ipaddr returns 192.168.1.254 and 192.168.1.1.
  • On Windows Tftpd64, run as Administrator, allow UDP port 69 in Windows Firewall, and select the 192.168.1.254 interface (not 127.0.0.1).
  • On Linux, filenames are case-sensitive and must match U-Boot's expected filename character for character.

Router Won't Boot After Flashing / Legacy NMBM Conflict

  • From U-Boot bootmenu, select [4] Boot recovery system from NAND (if installed) or [2] Boot system via TFTP to boot initramfs-recovery.itb in RAM.
  • If switching from a legacy NMBM firmware and UBI refuses to mount, run in U-Boot console: 
    ubi part ubi
run ubi_format
  • To reset U-Boot settings back to factory defaults, select bootmenu [a] or run run reset_factory && reset.
