Wi-Fi Roaming (802.11r/k/v) & SQM Anti-Bufferbloat

Practical post-install tuning for ImmortalWrt 25.12 on the Viettel SDMC NR3053 (adapted from hashcott's NR3053 optimization gist) to achieve seamless 2.4 GHz ↔ 5 GHz roaming and Waveform Bufferbloat Grade A.

Step 1: Install SQM & Verify Full wpad

ImmortalWrt 25.12 uses the apk package manager. Connect via ssh root@192.168.1.1 and install SQM: 

apk update
apk add luci-app-sqm sqm-scripts

Fast roaming (802.11r/k/v) requires a full wpad build (wpad-openssl or wpad-mbedtls), not wpad-basic-*. ImmortalWrt 25.12 for MT7981 usually pre-installs wpad-openssl; verify with: 

apk info | grep wpad
# If only wpad-basic-* is installed, swap it:
# apk del wpad-basic-mbedtls && apk add wpad-openssl && reboot

Step 2: Configure Wi-Fi + 802.11r/k/v Roaming

Use the same SSID and password on both 2.4 GHz and 5 GHz with WPA2 (psk2, best roaming compatibility across phones and laptops), non-DFS channel 36 (HE80) on 5 GHz, and channel 6 (HE20) on 2.4 GHz. Edit SSID and PASS below and paste into SSH: 

# ==== EDIT YOUR WIFI CREDENTIALS ====
SSID="YourWiFiName"
PASS="YourStrongPassword"
# ====================================

for i in $(uci show wireless | grep "=wifi-iface" | cut -d= -f1); do
  uci set $i.ssid="$SSID"
  uci set $i.key="$PASS"
  uci set $i.encryption='psk2'          # WPA2 — best 802.11r compatibility
  uci set $i.ieee80211r='1'             # Fast Transition (802.11r)
  uci set $i.ft_over_ds='0'
  uci set $i.ft_psk_generate_local='1'
  uci set $i.mobility_domain='a1b2'     # Must match across both bands
  uci set $i.ieee80211k='1'             # Radio Resource Measurement (802.11k)
  uci set $i.bss_transition='1'         # BSS Transition Management (802.11v)
  uci set $i.disassoc_low_ack='0'       # Prevent prematurely kicking weak clients
  uci -q delete $i.ocv
done

for r in $(uci show wireless | grep "=wifi-device" | cut -d= -f1); do
  band=$(uci -q get $r.band)
  uci set $r.disabled='0'
  if [ "$band" = "2g" ]; then
    uci set $r.channel='6'              # Non-overlapping 2.4 GHz channel (1/6/11)
    uci set $r.htmode='HE20'            # 20 MHz is most stable on 2.4 GHz
  elif [ "$band" = "5g" ]; then
    uci set $r.channel='36'             # Non-DFS 5 GHz channel (36/40/44/48)
    uci set $r.htmode='HE80'            # 80 MHz balances speed & stability
  fi
done

uci commit wireless
wifi reload

Verify both radios received identical roaming parameters:

uci show wireless | grep -E "ssid|encryption|ieee80211r|ieee80211k|bss_transition|mobility"
iwinfo

Step 3: Configure SQM/cake Anti-Bufferbloat

First confirm your WAN interface name (typically wan or pppoe-wan):

ip route show default
MT7981 CPU Ceiling for SQM/cake
cake runs on the CPU (single-threaded per direction). On the MT7981B, cake comfortably shapes up to ~250–300 Mbps per direction. Set download/upload limits to ~85–90% of your ISP speed, capped around 250–300 Mbps so sirq stays below ~30%. 
[ -z "$(uci -q show sqm.@queue[0])" ] && uci add sqm queue >/dev/null
uci set sqm.@queue[0].enabled='1'
uci set sqm.@queue[0].interface='wan'        # Change if using pppoe-wan
uci set sqm.@queue[0].download='250000'      # kbit/s (250 Mbps — tune to your line)
uci set sqm.@queue[0].upload='300000'        # kbit/s (300 Mbps)
uci set sqm.@queue[0].qdisc='cake'
uci set sqm.@queue[0].script='piece_of_cake.qos'
uci set sqm.@queue[0].linklayer='ethernet'
uci set sqm.@queue[0].overhead='44'
uci commit sqm
/etc/init.d/sqm enable
/etc/init.d/sqm restart

Disable Flow Offloading (Required for SQM)

Software and hardware flow offloading bypass SQM queuing — disable both so cake actually shapes traffic:

uci set firewall.@defaults[0].flow_offloading='0'
uci set firewall.@defaults[0].flow_offloading_hw='0'
uci commit firewall
/etc/init.d/firewall restart

# Confirm cake is active on both upload (dev wan) and download (dev ifb4wan)
tc qdisc show | grep cake

Step 4: Tune & Verify Grade A

  1. Run the Waveform Bufferbloat Test while watching top -d 1 in an SSH terminal.
  2. Aim for Download/Upload Active latency < +20 ms and CPU idle > 15–20% (sirq < 30%).
  3. If active latency spikes in one direction, lower that direction's bandwidth by 20–30 Mbps (e.g., uci set sqm.@queue[0].download='250000' && uci commit sqm && /etc/init.d/sqm restart) and re-test.
