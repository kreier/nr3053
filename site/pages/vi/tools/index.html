Công cụ & Gỡ lỗi thường gặp

Tài liệu sử dụng bộ công cụ nr3053-tools và hướng dẫn xử lý các lỗi phổ biến nhất khi nạp firmware qua Web Failsafe, SCP, TFTP hoặc UART trên Viettel SDMC NR3053.

Bộ công cụ quytttb/nr3053-tools

Các tiện ích Python chạy trên máy tính dành riêng cho router Viettel SDMC NR3053:

Công cụ Chức năng
unlock_nr3053.pyTải bản sao lưu cấu hình của ROM gốc, vá bật SSH/Telnet rồi tải ngược lên router (mật khẩu SSH trở thành admin).
factory/patch_factory_throughwall.pyCông cụ offline vá bản dump Factory chuẩn 2 MiB của NR3053 với giá trị hiệu chuẩn xuyên tường đã xác minh, in SHA-256 trước/sau và không tự ghi lên router.
 
# Cài đặt nr3053-tools
git clone https://github.com/quytttb/nr3053-tools.git
cd nr3053-tools
python3 -m pip install -r requirements.txt

# 1. Mở khóa SSH/Telnet (sau factory reset, mật khẩu là S/N dưới đáy máy)
python3 unlock_nr3053.py --password SERIAL_NUMBER_CUA_BAN

# 2. Tùy chọn: Patch Factory xuyên tường offline (file dump đúng 2 MiB)
python3 factory/patch_factory_throughwall.py stock_Factory.bin
python3 factory/patch_factory_throughwall.py --check stock_Factory.throughwall_mtd_Factory_0x0-0x200000.bin

Các lỗi thường gặp & Cách khắc phục

Không mở được trang Web Failsafe

  • Đảm bảo cáp mạng cắm vào cổng LAN (không phải WAN) và máy tính đã đặt đúng IP tĩnh: 192.168.1.2/24 (với U-Boot gốc) hoặc 192.168.1.254/24 (với U-Boot ImmortalWrt).
  • Tắt Wi-Fi và VPN trên máy tính trong khi flash; mở trình duyệt ở tab ẩn danh để tránh cache cũ.
  • Kiểm tra bạn đã giữ đúng nút MESH (không phải Reset) trước khi cắm điện và nhả khi đèn chuyển sang xanh lá đứng yên (~5 giây).
  • Một số lô NR3053 đời đầu không có Web Failsafe trong U-Boot gốc — hãy chuyển sang Cách 2 (Mở SSH).

Lỗi scp báo giao thức hoặc subsystem

Dropbear SSH trên ROM gốc không hỗ trợ SFTP. Hãy thêm cờ -O để dùng giao thức SCP cũ (hoặc dùng WinSCP chế độ SCP trên Windows):

scp -O immortalwrt-mediatek-filogic-viettel_nr3053-bl31-uboot.fip root@192.168.1.1:/tmp/fip.bin

mtk_uartboot báo Handshake timeout hoặc trắng màn hình sau FIP received

  • Kiểm tra TX/RX đã đấu chéo (TX mạch nạp ↔ RX bo mạch) và mạch chạy đúng mức 3.3 V (tuyệt đối không dùng 5 V).
  • Chạy lệnh mtk_uartboot trước rồi mới cắm nguồn cho router.
  • Không mở picocom hoặc PuTTY cùng lúc khi mtk_uartboot đang chạy trên cùng cổng COM/ttyUSB.
  • Ngay khi hiện FIP received, nhấn Ctrl+C ở cửa sổ mtk_uartboot và mở picocom / PuTTY trong 1–2 giây.
  • Kiểm tra đúng file RAM payload cho NR3053 (bl2-viettel-nr3053-ram.bin), không nhầm sang file của Viettel 32X6.
  • Nếu bị treo ở tốc độ nạp cao, thêm cờ --bl2-load-baudrate 115200.

TFTP timeout / Không tải được file

  • Kiểm tra IP máy tính đúng là 192.168.1.254/24 (serverip mặc định của U-Boot ImmortalWrt), không Gateway, đã tắt VPN.
  • Trong U-Boot, chạy printenv serverip ipaddr để xác nhận là 192.168.1.254 và 192.168.1.1.
  • Trên Windows Tftpd64: chạy quyền Administrator, mở Firewall cho UDP cổng 69 và chọn đúng card mạng 192.168.1.254 (không chọn 127.0.0.1).
  • Trên Linux, tên file TFTP phân biệt chữ hoa/thường và phải trùng khớp từng ký tự với tên U-Boot yêu cầu.

Router không khởi động sau khi nạp / Xung đột NMBM cũ

  • Trong bootmenu U-Boot, chọn [4] Boot recovery system from NAND (nếu đã cài) hoặc [2] Boot system via TFTP để chạy initramfs-recovery.itb trên RAM.
  • Nếu chuyển từ firmware có NMBM cũ và UBI không nhận phân vùng, chạy trong console U-Boot: 
    ubi part ubi
run ubi_format
  • Để đặt lại toàn bộ cấu hình U-Boot về mặc định, chọn mục [a] trong bootmenu hoặc gõ run reset_factory && reset.
